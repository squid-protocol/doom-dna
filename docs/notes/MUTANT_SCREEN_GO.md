# Mutant screen: gore (Go) engine (built and validated 2026-11-27; no lesion outcome read)

gore is the Go translation of doomgeneric (`build/gore`, recipe `demo/harness/build_gore.py`). This note records how the schemata engine for it was built on the pattern of the C# one (`build_cs.py`, `E13Mut.cs`) and what the validation showed. **Every lesion is compared with gore's own clean digest** (self-differential), because gore already diverges from chocolate-doom.

## Files (all new; `schemata.py` and the other engines are untouched)
| file | job |
|---|---|
| `demo/harness/mscreen/schemata_go.py` | registers `go` into `schemata.LANGS`, Go emitters, selection of the simulation functions; `schemata.instrument(src, "go", ...)` works as for C and C# |
| `demo/harness/mscreen/gotypes/main.go` | go/types facts (stdlib only): final type of every integer literal and binary operand, `x++` operand types, statements whose deletion would leave a local variable unused |
| `demo/harness/mscreen/e13mut.go` | runtime (package `gore`): `E13_MUT`, `E13_REF`, `E13_VERDICT`, `E13_NODIGEST`, `E13_PROFILE`, generic lesion helpers |
| `demo/harness/mscreen/build_go.py` | work copy of `build/gore` (never modified), two small patches, instrumentation, compile loop, manifest |
| `demo/harness/mscreen/validate_go.py` | clean digests, determinism, zero-lesion replay, switch-vs-classical equivalence, profile check; also the launch recipe |
| `demo/harness/mscreen/runner_go.py` | the phenotype runner for gore (runner.py hardcodes the other launch recipes); same store schema |

## Design
* **No ternary in Go**, so every lesion is a call to a generic helper that evaluates the operands once, in the original order, and runs only the selected operation: `e13Lt/Le/Gt/Ge/Eq/Ne[T](id, l, r)`, `e13Add/Sub/Mul/Div/And/Or[T]`, `e13Shl/Shr[T,S]`, constants `e13K[T](id, new, old)`, `x++` as `x = e13Inc[T](id, x)` (if/else for impure operands). `&&`/`||` use the lazy form `e13On(id) && (A || B) || e13Id != id && (A && B)`; condition negation is `((C) != e13On(id))` (also covers `!(cond)` for the parenthesis-free `if`); deleting a logical `!` is `((X) == e13On(id))`; statement deletion is `{ if !e13On(id) { stmt } }`.
* **No implicit conversions**: the explicit type argument `T` comes from go/types (`gotypes/main.go`), not from guessing: an untyped constant takes the type its context gives it (inner parts of an untyped constant expression such as `8 * (1 << FRACBITS)` take the type of the converted whole).
* **Unused variables.** The guarded block keeps the original statement, so the schemata build cannot produce "declared and not used". The same deletion by a source patch could, so statement deletions that would leave a local variable with no remaining read are pre-dropped (row `pre_drop = unused`, listed in the manifest `dropped`); every kept lesion therefore also compiles as a classical patch. A compile-error fallback for "declared and not used" and "missing return" exists in `build_go.py` as in `build_cs.py`. Integer constants whose new value does not fit the type are pre-dropped (`range`). The compile loop (`go build -gcflags=-e`, errors attributed to the innermost `/*S<id>*/ ... /*E<id>*/` schema) drops the rest.
* **Division by zero** panics at run time (`const_zero` on a divisor, `*` to `/` with a zero operand): an uncaught panic is outcome `crash`. A classical patch of `x / 5` to `x / 0` would not compile (Go rejects constant division by zero), so such lesions are schemata-only; none turned up in the validation samples.
* **Never lesioned**: array lengths, index and slice index expressions (out of range is a panic, not a role), case values, keyed-element keys, `const` declarations, `unsafe.Sizeof`, string/rune/float literals. Shift lesions are kept (kind `shift`) and excluded from the primary E15 analysis as for the other ports.
* **Same 15 kinds and ids**: ids below 10,000 original (relational, equality, arithmetic, logical, shift, constant +1), from 10,000 the v2 classes (sdl, negate, const_zero, const_dec, const_toggle, arith2, bitwise, not, incdec). `+` on strings and non-numeric types are skipped.
* **Functions screened**: the translation keeps chocolate-doom's file order, so the 226 functions from `t_MoveCeiling` to `p_PlayerThink` minus the save-game block, `p_setup`, `p_tick`, the `init` functions (the 16 files of the C screen: p_enemy p_map p_maputl p_sight p_mobj p_user p_pspr p_inter p_doors p_floor p_ceilng p_spec p_switch p_plats p_lights p_telept; in gore all one file, `doom.go`). Rendering, menu and sound are not instrumented.
* **Runtime / hooks.** `build_go.py` patches the work copy only: (1) the digest line also calls `e13Check` with the 19 values (early abort at the first mismatch against `E13_REF`; the compared columns are those of `E13Mut.cs`: 1, 2, 4..18, angle skipped while the reference player is dead) and is not written when `E13_NODIGEST` is set; (2) `e13Finish()` is called where the timedemo ends, before gore's `i_Error("timed ...")`: it writes the profile and the verdict (`end <rows>`) and exits, so gore no longer needs to be killed after the timedemo line (the unmodified engine still does: used for the clean digests, stopped by process group 3 s after the line).
* **Launch recipe** (from `diagnosis/run_cases.py`): scratch cwd, the IWAD-swap demo symlinked as `DEMOIWAD.WAD`, `-iwad DEMOIWAD.WAD -timedemo demo1 -nodraw -nosound -nomusic`, `HOME`/`XDG_*` = the scratch dir, `SDL_VIDEODRIVER=dummy`, `nice -n 10`, own process group (never `pkill -f`). Gore crashes on external-lump loads, so the IWAD-swap demos are used.

## Build numbers
* **Functions**: 226 instrumented (224 carry lesions; `getSector`, `getSide` have none), each with one `e13Enter` at the top of its body.
* **Lesions kept: 9,053** (8,724 without the 329 shift lesions, the primary-analysis set). By kind: sdl 2,205; const_toggle 1,447; negate 980; equality 863; const_dec 539; const_zero 539; constant 539; arithmetic 440; relational 363; shift 329; arith2 323; logical 201; bitwise 170; incdec 114; not 1 (the translation writes `x == 0`, not `!x`). Ids: 0 to about 2,700 original, 10,000 to 16,401 v2.
* **Dropped: 85**: 81 statement deletions pre-dropped (would leave a variable unused), 3 integer constants that do not fit their type (one literal 512, three kinds), 1 by the compile loop (`/` to `*` in `p_PlayerThink`; one compile iteration, 2 errors). The compile loop ends after one iteration because the explicit types from go/types keep the schemata well typed.
* **Demos**: 77 run. On the unmodified gore engine 74 complete, **excluded: v0084 (Go nil-pointer panic at row 2,875), f0074 and g0018 (infinite loop in clean gore, digest stops at 76 and 528 rows; 60 s timeout)**. The instrumented build with no lesion crashes or hangs on exactly the same three.
* **(1) Zero-lesion replay**: E13_MUT unset: **74/74** completed demos give a per-tic digest file byte-identical to gore's clean digest AND the early-abort verdict `end <rows>` (run twice, before and after a rebuild).
* **(3) Clean digests and determinism**: `screen/go_v2/clean/<demo>.txt` (unmodified engine, digest rows 76 to 4,000 per demo); repeat run `clean_repeat/`: **77/77** identical (byte-identical digests and the same status, including the three excluded demos).
* **(2) Switch vs classical rebuild**: **35/35** lesions identical on all 74 demos (outcome, first tic and mismatch mask per demo): 20 random (seed 1) and 15 stratified, one of each kind (seed 2: const_toggle, const_zero, const_dec, arithmetic, equality, logical, bitwise, relational, shift, negate, sdl, arith2, constant, incdec, not). No drawn lesion needed a classical patch that does not compile. (Hang lesions are compared with a 6 s timeout in this check; the screen uses 6 x the clean time, floor 15 s.)
* **(4) Profile** (`E13_PROFILE`): format `F fid count first_tic` and `S id count` as for the other ports; 74 demos give 198 of 226 functions entered by at least one demo (the 28 never entered are the usual shareware gaps: ceilings, crushers, strobe/light specials, brain/keen/pain-death actions, stairs, plats in stasis, overrun helpers) and 0 profile lines with an unknown id; 226/226 `e13Enter` calls present exactly once. Cross-check against chocolate-doom's `choc_phenotypes.sqlite` reach table: 182 name-agree functions, 175 entered in both, median gore/chocolate entry ratio 1.003 over 7,236 (function, demo) pairs (10th to 90th percentile 0.82 to 2.55: gore's play diverges from chocolate's on most demos).
* **Cost**: clean instrumented run 0.12 s on average (max 0.40 s; the unmodified engine needs the 3 s wait after the timedemo line). Full screen: **302,649** (lesion, demo) jobs (a lesion runs only on demos whose clean profile executed its site; 7,197 of the 9,053 lesions are executed by at least one demo). A 2,971-job trial slice (function `p_Move`) ran at 3 workers in 165 s = 0.055 s per job, so the full screen is about 4.6 hours at 3 workers plus hang time (15 s each, floor), less than the other ports. **Recommended: `--workers 3`, `nice -n 10` (built into the launch), `--maxload 10`** (the runner pauses above that load); more workers do not help on a shared box.
* The runner trial slice and the validation samples were only checked for agreement; no lesion outcome table was read.
