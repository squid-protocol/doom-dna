# E15 (DRAFT v2, 2026-11-26): a mutant screen defines function roles; do roles form call-graph neighbourhoods that recur across ports?

**Status: REGISTERED (v3) by the commit that adds the analysis code (`demo/harness/mscreen/analysis/`: `roles.py`, `graphs.py`, `tests.py`, `pipeline.py`, `run_e15.py`, `synth.py`), before any result database was queried (the databases were read only for job counts).** Analysis code was validated on synthetic screens (`synth.py`): with planted role groups the pipeline recovers them (H1a, H2, H3, H4 pass; PC1 pass), with no planted structure H1a fails and H2-H4 are labelled exploratory. The synthetic test changed three design details that are now part of the registration (below, marked v3). v1 (commit 555db29) was reviewed by a Claude subagent and by Gemini (read-only, blind to results; Gemini's text: `results/e14/E15_review_gemini.txt`) and informed by `docs/notes/LIT_REVIEW_MUTANT_SCREEN.md` (about 95 verified references); both reviews found v1 not yet testable. Reconciliation in section D.
**Disclosure.** A first launch of the two screens (chocolate-doom, managed-doom) ran for about 25 minutes before the reviews showed defects in the tooling (first-mismatch column only, function-entry rather than site-level reach, overloaded-method collisions, no timeout retry). That run was stopped; its two partial databases (about 2,000 and 3,500 results) were archived **unread** (`screen/discarded_v1/`); the screens were rebuilt and restarted from zero. No phenotype of any lesion has been looked at. Thresholds below come from reasoning and from a simulation on synthetic data (section C; the first version of this draft asserted simulation values before running it, and they were wrong, see section C), **not** from any screen result; the E14 pilot and confirmatory data are not used for thresholds either.

## Idea
Forward genetics: lesion every function in small ways, assay with deterministic demo replay, define a function's **role** by the **phenotype** of breaking it. The 42 demos are a **shared coordinate system** across ports, so phenotypes from different engines are directly comparable without first matching functions by name or structure. Framing against the literature: each ingredient has precedent (mutant schemata, Untch et al. 1993; kill patterns as fingerprints inside one program, Metallaxis-FL; phenotype-based orthology, McGary et al. 2010), but we found no work that defines roles by lesion phenotype and matches functions across independent implementations; we claim only "adapting forward genetics to cross-implementation role inference".

## Owner's prediction (headline)
**The screen reveals a modest number of groups; the host functions of a group form tight neighbourhoods in the call graph beyond source-file locality; the same groups recur across ports and translations.**

## Measurement (frozen)
* **Lesion-demo observation:** a lesion is observed on a demo only if its **site is executed** in the clean run (per-site counters, `sitereach`); otherwise there is no observation (exactly no effect). Outcomes: killed (first diverging tic; bitmask of every mismatching state column, RNG bit kept separately), same (**executed but not detected**: indistinguishable from an equivalent mutant), crash, hang (rerun once; then excluded from similarity and tabulated). Comparison columns are the common columns; dead-angle-ignoring; **strict mode is not stored and is not reported**.
* **State class** of a kill: from the mismatching-column bitmask **excluding the gameplay RNG index**: player (position, angle, health, armour, weapon, ammo), world (monster fingerprint), sector, keys; several can apply (multi-label).
* **Informative lesion:** observed on >= 1 demo. **Function phenotype** (eligible if >= 4 informative lesions): per demo, the fraction of its observed lesions that kill (missing where none observed); the median log first-divergence tic over kills; the non-RNG state-class distribution. **Clean entry counts are not part of the phenotype** (they would make split-half matching tautological).
* **Function distance:** D = 0.6 * (mean absolute difference of kill fractions over co-observed demos) + 0.2 * (absolute difference of median log first tic, scaled to [0,1]) + 0.2 * (Jensen-Shannon divergence of the class distributions), requiring >= 5 co-observed demos; a pair below that is **missing**, handled by imputing the maximum distance 1 (sensitivity: dropping the pair). Ablations: Jaccard of failing sets, Ochiai, d-vector Hamming.
* **The inert class (v3):** functions none of whose observed lesions was detected on any demo (inert or untested; carries no role information) are likewise excluded from H1a-H4 and listed. **The "kills everything" class:** functions whose kill fraction is >= 0.9 on >= 90% of their observed demos form a named class (expected: core thinkers and movement), **excluded from group counts and from H2-H4 statistics** and listed.
* **Build-dependent lesions** (shift operators `<<`, `>>`): excluded from the primary analyses, reported with them in a sensitivity run.
* **Graphs:** G1 static call graph (scanner, confident edges, undirected, distance capped at 6); G2 state-table edges (action functions referenced from the mobj and weapon state tables to the functions that dispatch them: P_MobjThinker/P_SetMobjState and P_SetPsprite for chocolate, the equivalent managed-doom dispatch); **G3 = G1 union G2 is primary**; G1 alone is a sensitivity analysis. All null models use the **induced subgraph of screened simulation functions**, not the whole program; disconnected pairs get distance 7. A dynamic co-entry graph is descriptive only (it restates reach).

## Hypotheses (hierarchy: H1a is a gate; H2-H4 are the confirmatory family, Holm at 0.05; H5, H6 exploratory)
* **H1a (gate: a discrete grouping exists; v3).** Function-level hierarchical clustering (average linkage on D, eligible non-hot non-inert functions). The **primary null is Gaussian (SigClust-style)**: 200 datasets with rows drawn from a multivariate normal with the observed per-demo means and covariance (a continuum with the same correlations and no clusters), the observed-demo mask kept, values clipped to [0,1], tic and class rows permuted. k = the k (2 to min(40, n/4)) with the largest gap statistic; **p = the share of null datasets whose own largest leave-one-out gap is at least as large** (accounts for choosing k; minimum p with 200 nulls is 0.005). A **secondary any-structure null** permutes kill fractions within each demo column among the functions that observe that demo (100 nulls). Stability from two bootstraps (demos stratified by family; 80% function subsamples) with best-match Jaccard. Pass in **both** ports: Gaussian p < 0.01 and >= 60% of functions in groups with stability >= 0.6. If H1a fails, H2-H3 are reported as exploratory (H4 is a function-level result and is not gated by H1a). *v3 note:* the draft's permutation-within-identical-mask null was dropped because nearly every function has a unique observed-demo mask (the permutation would do nothing), and a permutation null cannot distinguish discrete groups from a correlated continuum.
* **H1b (descriptive, not a test): the group count k.** Expectation 4 to n_eligible/5; domain guess about a dozen (monster chase/attack, projectiles, movement/collision, geometry/blockmap, sight, door/floor/ceiling/platform/light specials, teleport, weapons/player, damage, spawn). Reported with its bootstrap range.
* **H2 (call-graph neighbourhoods; primary statistic).** Over groups with >= 5 eligible functions, the size-weighted mean of (null mean minus observed mean pairwise G3 distance) is >= **0.5 hops**, permutation p < 0.0167 (10,000 permutations of group labels among functions **within strata of reach count and degree**, cross-file host pairs only so the effect is not file locality). Reported: per-group tables, same-file pairs separately, rewired-graph null, and the share of groups individually significant.
* **H3 (recurrence across ports).** Groups from chocolate-doom and managed-doom correspond: **adjusted mutual information (AMI) >= 0.30** between the two ports' group assignments over name-agree function pairs (names identical after stripping the C prefixes `EV_ P_ A_ T_ PIT_ PTR_`; generic helper names and the hot class excluded), p < 0.0167 against a **function-label permutation within reach strata**; a minimum of **60 name-agree pairs** with >= 4 informative lesions on both sides or the test is "inconclusive for power". Mutual best match is reported normalised by min(k_ch, k_md) and against a simulated chance level. Basis for 0.30: the section C simulation gives AMI about 0.6 when 20% of functions play a different role in the other port and about 0.3 when 45% do (12 groups, moderate phenotype noise), so 0.30 requires that roughly half or more of the functions keep their role.
* **H4 (role matching recovers known orthologs, beyond reach).** Candidate pool = managed-doom eligible non-hot functions; for each chocolate eligible non-hot function with a name-agree partner in the pool, the partner's **rank** by D. Because roles are shared by many functions, rank recovery of one named partner is capped by group size (the section C simulation: top-5 about 0.35 at best with 12 groups of about 12 functions), so the threshold is **relative**: top-5 recovery >= max(**3 x chance** (chance = 5 / pool size), **N0 + 15 points**, **0.5 x the within-function ceiling** (PC1 split-half top-5 in the same pool)), and top-1 >= N0 + 10 points; p < 0.0167 (cluster bootstrap by function; Holm family). Reported: chance, N0, ceiling, recovery at the group level (partner in the same group), reciprocal best hits (Moreno-Hagelsieb) and one-to-many matches.
* **H5 (exploratory: conserved role, diverged structure).** Spearman between E12 structural distance (and size ratio) and D among phenotype-matched pairs; listing of the structurally most divergent yet phenotype-matched pairs.
* **H6 (exploratory: E12 homology and the ortholog conjecture).** (a) E12 strong-tier pairs (exact/twin/xtwin/seed) share a group more often than extension-tier pairs and than random pairs (proportions with function-clustered CIs; confusion matrix; 40 random disagreements audited by reading both functions); (b) sibling functions within one port versus cross-port counterparts (Nehrt et al. 2011 warns that within-species paralogs can match better than cross-species orthologs).

## Controls
**Positive** (gates for the claims they name): **PC1f function-level reliability (v3; gate for H4):** each function's lesions are split at random into halves (functions with >= 8 informative lesions, not hot or inert); the half-phenotype's rank of its own other half among all such functions must give top-1 >= **0.20** and top-5 >= **0.50** in each port (chance = 1/pool size; the earlier top-1 >= 0.70 was unattainable for single functions with 4 lesions per half; the synthetic screen puts function-level signal at top-1 0.5-0.8 when each function carries its own profile). **PC1g group-level reliability (v3; gate for H1a-H3):** the groupings obtained separately from the two halves agree with adjusted mutual information >= **0.40** in each port. **PC2 identity ceiling:** a screen of a near-clone port (prboom-plus) recovers identical-text functions as top-1 for >= 90%; **planned, gated**: until it is run, the cross-lineage claims in H3/H4 are labelled "C#-versus-C only, no clone ceiling". **PC3 known orthologs:** the E14 agree-stratum functions are checked as a descriptive binomial interval (not a gate; it overlaps H4). **PC4** (descriptive): phenotype groups against source files (adjusted Rand index above the permutation null). **PC5 determinism:** the zero-lesion replay and a repeated 200-lesion sample reproduce exactly on both ports, repeated at a different machine load.
**Negative:** N0 clean entry-count profile only (clustering and matching on reach alone; H1a-H4 must beat it); N1 degree-preserving rewired G3; N2 size- and reach-matched random function sets; N3 function-shuffled phenotypes; N4 decoy matcher (random one-to-one within the same file); N5 lesion-kind control (clustering lesions by operator class alone must not reproduce the groups); N6 the 15 name-disagree functions as a descriptive contrast (not a pure negative control).

## Analysis rules
Unit of analysis = function (cluster bootstrap over functions, 10,000 resamples). One scalar test per confirmatory hypothesis, Holm over H2-H4. **Minimum evidence for power:** >= 60 eligible non-hot functions per port, >= 5 qualifying groups for H2, >= 60 name-agree pairs for H3; otherwise "inconclusive for power", never a null. Asymmetric screens are analysed on the matched subset. All analysis code (`analyze_*.py`) is committed before any database is queried; a deviation is reported as such.

## Pre-declared uninterpretable outcomes
One giant hot cluster plus singletons; group count that tracks demo family (monster-on versus bot) rather than function role; recurrence explained only by clean reach (N0); recurrence explained only by inherited C-family code or by a faithful translation (managed-doom is a faithful port; a pass says the matcher and the names agree with behaviour, not that the matcher is right where it disagrees with the names); results driven by fewer than 10% of functions.

## Limits
Simulation functions only (rendering, menu and sound are not exercised); demos reach part of each function and "same" cannot separate equivalent from untested lesions; one-token lesions; the shared inherited code of the C family; functions split or merged by a port have one-to-many roles; the static graph misses calls through function pointers beyond the state tables (G2 covers the dominant dispatch); screens of a single translation with identical game behaviour.

## C. Threshold basis
No screen data. `demo/harness/mscreen/simulate_thresholds.py` (committed with this registration) simulates two ports whose functions share 12 latent role groups (140 functions, 42 demos, per-function reach masks, 80 name-agree pairs); a fraction `swap` of functions plays a different role in the second port, plus measurement noise. Output (mean over 60 replicates; AMI of recovered groups, top-1 and top-5 rank recovery of the partner, chance top-5 = 0.04):

| swap | noise | AMI | top-1 | top-5 |
|---|---|---|---|---|
| 0.00 | 0.15 | 0.87 | 0.04 | 0.39 |
| 0.20 | 0.15 | 0.60 | 0.03 | 0.34 |
| 0.45 | 0.15 | 0.32 | 0.02 | 0.23 |
| 0.70 | 0.15 | 0.11 | 0.01 | 0.15 |
| 0.00 | 0.30 | 0.47 | 0.02 | 0.22 |
| 0.20 | 0.30 | 0.32 | 0.02 | 0.18 |

Reading: AMI separates role conservation levels well (hence H3's 0.30); top-k recovery of a single named partner is limited by group size when roles are shared (hence H4 is stated relative to chance, N0 and the within-function ceiling, and group-level recovery is reported). H2 (0.5 hops): a null in which group labels are random among reach- and degree-matched functions has mean difference 0 by construction; 0.5 hops is about a fifth of the typical pairwise distance in a connected game-logic subgraph (about 2-3 hops) and is the smallest difference the owner would call "tight".

## D. Reviews and reconciliation (2026-11-26)
**Both reviews agreed (adopted):** cluster at the function level (lesion-level groups are functions in disguise); severity/hot functions dominate similarity (named hot class, first tic and state class added to the distance); minimum co-observed demos and the 0/0 case; gap-statistic null and the k band were untestable (null defined, k demoted to descriptive); H2 nulls (restrict to the screened subgraph, cross-file pairs, degree matching, function-pointer dispatch via state-table edges); cross-port tests (AMI, label permutation within reach strata, min-k normalisation, power minimums); reach at function entry confounds "same" with "unreached" (site-level counters); hangs rerun and excluded; thresholds fixed at registration (not "to be tightened"); H1 as a gate with a defined multiplicity family; controls tightened (PC1 definition and ties, PC2 planned and gated, PC3 descriptive, PC4 demoted, PC5 on both ports and across load); uninterpretable outcomes pre-declared.
**Gemini only (adopted):** clean reach removed from the phenotype and an N0 clean-reach baseline added (PC1 would otherwise be tautological); RNG masks the first-mismatch class (the early-abort comparison now records the mask of every mismatching column, RNG separate); overloaded C# methods collided in the function map (lesion rows carry the host function id); strict mode is not stored (claim dropped); `col = -1` coding specified; shift lesions as the build-dependent class; retries.
**Claude only (adopted):** per-site coverage; bootstrap both demos and functions; the ortholog-conjecture control; hierarchical testing; the explicit uninterpretable list.
**From the literature review (adopted):** baselines and metrics list (reciprocal best hits; Jaccard/Ochiai/d-vector ablation; per-lesion coverage; repeat-run stability; Altenhoff-style multi-proxy matcher scoring; sibling-pair control); framing of novelty as adaptation, not invention.
**Declined / deferred:** a learned phenotype-from-code baseline; a true dynamic caller-callee graph (no call-edge tracing in the engines; co-entry is descriptive); causal tic ordering along call edges (exploratory idea, later).
