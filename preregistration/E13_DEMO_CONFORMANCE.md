# DOOM-E13: behavioural conformance of DOOM engines under deterministic replay, and a differential localiser

**Status: REGISTERED by the commit that adds this file in this form (2026-11-26), after two independent design reviews (a Claude subagent and Gemini, both read-only and blind to results) were reconciled in section D. The registered runs (Parts A, B, C) are read only after this commit. Pinned artifacts: `preregistration/E13_PINS.txt`.** Harness: `demo/harness/`; tool: `demo/harness/difflocalize/`.

## 0. What this is, and what has already been seen (disclosure)
E13 began as an exploratory programme (notes: `docs/notes/DEMO_STUDY_PLAN.md`; per-demo tables `demo/phase*.csv`). **Already seen, so not predictions here:** the conformance results of 14 engines on three demo sets (three stock demos; 300 "sticky" random demos, seed 20261125; 200 "chaos" demos, seed 777; 47 bot demos), including: the six C engines, Managed Doom (C#) and doom-ascii matched the reference on every demo; Mocha 290/300 sticky and 191/200 chaos; room4doom 45/300 sticky, 1/200 chaos, 12/47 bot (47/47 once the demo-header "no monsters" byte is rewritten to 1); puredoom 52/300 and 2/200 (first difference in the weapon field); Kocoa and gore 0 on every monsters-on set (gore 17/47 on bot demos); the root cause of gore's first failure (a loop-index bug in `p_CrossSubsector`; fixing it delays its median first divergence from tic 6 to tic 104). Also seen, and flagged: (i) a 12-mutant smoke run of the localiser, seed 20261126 (5 detected; hits mixed), which motivated variant B and is **not** part of the registered set (the registered set uses a fresh seed); (ii) an 8-mutant code test, seed 99 (2 detected); both anchor the M1 band below. A first 120-mutant run (seed 20261126) was started and **stopped unread** when the reviews showed the harness did not record what the registered analyses need; its outputs were deleted. **New here:** (A) the localiser's validity on injected bugs, and (B) replication of the conformance table on held-out demo seeds.

## A. Differential localiser: validity on injected bugs
**Tool (tier 1).** Given a reference engine, a subject engine and one demo: (1) first diverging tic and field; (2) the first game tic whose sequence of gameplay-RNG calls, labelled by the calling function, differs, and the callers present in only one engine (the *symptom functions*); (3) *suspects* = the symptom functions plus their static callee closure from the scanner's call graph (`function_data.calls_out_to`), to depth D. **Variant A:** callees only; depth counts callee hops. **Variant B:** also seeds with the symptom functions' callers up to two levels, and the caller hops count toward the depth. With no RNG difference, a fixed field-to-function-family prior (`FIELD_FAMILY` in `locate.py`, written by someone who has seen the engines, so it is not blind) seeds the closure instead. Static call graphs miss calls through function pointers (thinker functions, state actions, traverse callbacks); that is a stated limit and is quantified by *reachability* below.
**Mutants.** 110 sampling attempts from the pooled mutation sites of 16 simulation files (p_enemy, p_map, p_maputl, p_sight, p_mobj, p_user, p_pspr, p_inter, p_doors, p_floor, p_ceilng, p_spec, p_switch, p_plats, p_lights, p_telept; 1,872 sites in function bodies only), **seed 20261201, without replacement, at most 2 mutants per mutated function**; one change per mutant (relational, equality, `+`/`-`, `&&`/`||`, shift, integer constant + 1). The universe **U** is the 230 functions defined in those files; whole call graph 2,431 functions. The mutated function is known from the scanner's database (nearest preceding definition; sites outside function bodies are excluded by construction).
**Detection set:** 45 demos: 20 sticky (seed 20261125), 10 chaos (seed 777), the 3 stock demos, and 12 replay-validated bot demos. A mutant is **killed** if any demo's digest differs from the reference engine's on any compared field (including the world fingerprint, keys held and the RNG index; `E13_WIDE`); a demo where the mutant crashes or times out (40 s) is **not** a divergence: a mutant whose only failures are crashes or hangs is reported as "crash/hang" and not scored. Mutants that do not build, survive, or only crash are reported (detection by file and by operator) but not scored for localisation. Tracing must not change behaviour: the harness asserts identical digests with and without the trace on 6 demos before any mutant runs.
**Localiser input.** The primary demo is the **earliest-diverging** failing demo (ties: list order). Also reported: a seeded random failing demo and the median failing demo.
**Baselines (registered, computed for every killed mutant).** (a) random suspects of the same size drawn uniformly from U (expected hit probability = size / |U|); (b) a degree-preserving rewiring of the call graph (20 rewired graphs; the same symptoms, depth 3); (c) the field-family prior applied to every killed mutant (paired); (d) the symptom functions alone (depth 0). The **hot-function baseline** (top functions by execution frequency) is declined: no profile is collected; stated limit.
**Stratification and uncertainty.** Hit rates are reported overall and for the **non-trivial subset** (the mutated function is not itself a symptom function, i.e. depth > 0), by whether the mutated function calls the RNG directly, by operator and by file. Every rate carries a Wilson 95% interval and a **cluster bootstrap by mutated function**. Paired comparisons use an exact McNemar test. Misses are split into *statically unreachable from the symptoms at any depth* and *reachable but deeper than D*.
**Predictions (made before any registered-run result was read).**
* **M1 (descriptive):** between 20% and 55% of buildable mutants are killed.
* **P1 (primary):** among killed mutants the mutated function is in the variant-A suspect set at depth <= 3 in at least **50%**, **and** that beats random same-size suspects by at least **20 percentage points** (cluster-bootstrap 95% lower bound of the lift above 0).
* **P2 (primary):** on the non-trivial subset, depth <= 3 hit rate at least **35%** and lift over random at least **15 points**.
* **P3:** the median depth-3 variant-A suspect set is at most **30% of |U|**.
* **P4 (exploratory, not confirmatory):** variant B versus A compared at matched suspect-set size; report only. Variant B was motivated by the smoke run.
* **P5a:** an RNG-caller difference exists for at least **70%** of killed mutants. **P5b (paired, on the mutants where it exists):** A's depth <= 3 hit rate exceeds the field-prior's by at least **15 points**.
* **P6:** the depth-3 hit rate exceeds the rewired-graph null's mean by at least **20 points**.
* **P7:** the hit rate on a random failing demo is within **10 points** of the earliest-demo rate.
No multiplicity correction is claimed: P1, P2 and P5b are the primary tests; everything else is descriptive.
**Also reported, not predicted:** the cross-language case (gore): the root cause `p_CrossSubsector` is in the variant-A suspect set at depth 3 (57 of 923 functions within three hops; computed after the cause was known, so post hoc); and the survivor sensitivity (survivors and crashes counted as misses, a different quantity).
**Not in scope.** Bugs in input parsing or configuration (for example room4doom's header-byte check) leave no RNG or call-sequence signature; mutants are small syntactic changes, not realistic translation errors, so Part A validates the method on injected same-engine bugs and says only the single gore case about real translation bugs.

## B. Replication of the conformance table on held-out demo seeds
New demos from the registered generators: **sticky 300 (seed 20261127), chaos 200 (seed 888), bot demos with seeds 6 to 11 on all maps (replay-validated, then de-duplicated; n reported)**. Engines and builds unchanged (no engine is modified). This is a **stability check of a known table** (Monte Carlo variation of the generators), not a test of generalisation to human play, DOOM 2 content or other modes, and 0 of n bounds a divergence rate only below about 3/n. **Nondeterminism and timeouts:** a demo that times out is re-run once; a second timeout is reported as a failure of that engine on that demo; the C engines are expected to be deterministic.
**Definitions.** *Strictly identical*: no difference on any compared field. *Gameplay-identical*: the same, ignoring the view angle on tics where the reference player is dead (a post hoc rule, implemented as the flag `--ignore-dead-angle`); **both are always reported**. Compared columns per engine are tabulated: world fingerprint and keys for the reference, the C family, doom-ascii, Managed Doom, Mocha, Kocoa and gore; no RNG index for prboom-plus, inter-doom and Kocoa; player-only digests for puredoom and room4doom (their rates are upper bounds). A common-column sensitivity table (player columns only, no RNG index) is added. The order of the compared fields is: leveltime, prndindex, x, y, z, angle, health, armor, weapon, ammo0-3, then nmobjs, mobjhash, sectorhash, cards; "first differing field" shares depend on this order. The room4doom header-byte rewrite was found post hoc and is reported separately, never inside R3's headline.
**Predictions (gameplay-identical).**
* **R1 (sharp):** the six C engines (doomgeneric, crispy-doom, prboom-plus, sdl-doom, inter-doom, doom-ascii) and Managed Doom: **100%** of every new set.
* **R2:** Mocha: between 92% and 99% on sticky and on chaos.
* **R3:** room4doom as recorded: sticky between 8% and 25%; chaos at most 4%; bot between 15% and 40%; on chaos the first differing field is the weapon in at least 50% of divergences.
* **R4:** gore and Kocoa: at most 2% on sticky and chaos; Kocoa on the bot demos (no monsters): **100%**; gore on the bot demos between 25% and 50%.
* **R5:** puredoom: sticky between 10% and 25%; chaos at most 3%; the weapon is the first differing field in at least 90% of its divergences; bot demos 100%.
* **R6:** Managed Doom and doom-ascii on the bot demos: 100%.

## D. Reviews and reconciliation (2026-11-26)
**Both reviews agreed (adopted):** narrowing needs baselines (random same-size suspects, the field-family prior, a rewired call graph; hot-function baseline declined) and a denominator that is the mutable universe, not the whole program; the depth-0 hit is partly circular, so hits are stratified by whether the mutated function is itself a symptom and by whether it calls the RNG; survivor selection bias is reported (detection by file and operator, survivor sensitivity) and the detection set now includes bot demos; the earliest-diverging demo is optimistic, so random and median failing demos are also run; mutants are sampled without replacement with a per-function cap, intervals are Wilson and cluster bootstrap, paired comparisons use McNemar; crashes and hangs are no longer scored as kills; function-pointer calls are a stated limit and reachability separates unreachable from too deep; variant B is compared at matched size and flagged exploratory; the smoke runs are disclosed and not part of the registered set; M5 is split into availability and a paired comparison; Part B is described as a stability check, tightened, extended to the bot demos, and reports strict and gameplay-identical with the post hoc rules coded as flags and per-engine columns tabulated; tracing must not change behaviour (asserted); artifacts are pinned.
**Adopted from Gemini only:** the five code defects (the wide columns were not enabled in the evaluator; crashes counted as kills; comment stripping broke column offsets; file-scope initializers were treated as function bodies; a space in a field-family name), all fixed before the registered run; a fresh post-review seed; a prospective case-study section.
**Adopted from the Claude review only:** reachability-at-any-depth reporting; the explicit ambiguity statement for the mutated-function label; the instruction to register nondeterminism and timeout handling.
**Declined:** the hot-function baseline (no profile is collected); the coverage-based classification of survivors (a bounded sensitivity figure is reported instead).
