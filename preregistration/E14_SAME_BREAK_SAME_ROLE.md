# E14 (DRAFT v2, 2026-11-26): do structurally matched functions play the same role? Break them the same way in several ports.

**Status: DRAFT v2.** v1 (commit db9ca39) was reviewed by a Claude subagent and by Gemini (both read-only, blind to results; Gemini's text is in `results/e13/E14_review_gemini.txt`); both found v1 close to uninterpretable. This version reconciles them (section D). It becomes registered only by a commit that follows a non-confirmatory pilot (Phase 0) and states the frozen sample, thresholds and power; nothing in Phase 1 runs before that commit.

## Question
Our name-blind matcher says function X in port P and function Y in port Q have the same structure. Do they have the same *role*? Test: apply the same one-token change at the aligned site in both, run the same deterministic demos, and compare how each port breaks relative to **its own unmutated self**.

## Phase 0: pilot (non-confirmatory, excluded from Phase 1)
12 functions (stratified: 6 high-conservation, 6 low), reference chocolate-doom, two targets: **prboom-plus** (the most diverged C port) and **managed-doom** (C#, independent source, 100% demo-identical on the exact-conformance set; includes E12 extension-tier matches, since it has few fingerprint twins). Report: baseline replay pass rate of each unmutated port on all 45 demos (ports that fail baseline are dropped or restricted to demos they pass); per-mutant **coverage** (was the site executed, in how many demos); equivalent/survivor rate by function; site-alignment dropout by port and conservation tier; build/crash/hang rates; between-function variance of the agreement score (for the power calculation); a manual audit of 30 random aligned sites (site-correspondence error rate; tolerance 15%). Tooling needed: a (line, column)-ordered site enumerator that works for C and C#, compiler-flag standardisation (`-O2 -fno-strict-aliasing`), self-differential scoring.

## Phase 1 (confirmatory, only after the pilot commit)
1. **Function sample.** Universe = gameplay (p_*-family) functions of the reference port with >= 6 lines, matched to at least one target by the E12 ladder (precedence: F0 exact/twin, then F1c, strictly one-to-one). Sample **30 high-conservation and 30 low-conservation** functions, stratified on size and on reference-demo coverage, **frozen (seed and list committed) before any mutant is built.** Conservation is defined on the reference side only.
2. **Panel.** Lineage strata, never pooled before a heterogeneity test: (S-near) crispy-doom, prboom-plus, inter-doom, doom-ascii, sdl-doom, doomgeneric (C, shared ancestry; **doomgeneric is not an independent lineage**); (S-far) managed-doom (C#), then Mocha (Java), Kocoa (Kotlin), gore (Go) if the pilot shows mutation tooling is tractable. The claim lives in S-far and in the low-source-similarity part of S-near.
3. **Site alignment.** Sites sorted by (line, column). Alignment by local-window match (operator, operand roles, neighbouring tokens), not by identical full-function operator sequence. Sites where the two functions' operators or operand roles disagree are dropped and tabulated (by port, tier, operator); constants that are macros in one port and literals in the other are dropped. At most 5 sites per function, stratified by operator, seeded.
4. **Signature and scoring.** Every mutant is scored **self-differentially** (mutated P against clean P), with `E13_WIDE=1`, `--ignore-dead-angle` reported alongside strict, and the **common column set** (no `prndindex`; reported separately where available). Crashes, hangs and build failures are a separate outcome, never a kill.
5. **Primary outcome (one).** Among aligned site pairs where **both** mutants are *reached* (executed by at least one demo) and **at least one** is killed: the Jaccard similarity of the two failing-demo sets restricted to demos that reach both sites. Compared as matched minus control, with a **cluster bootstrap by function** (function is the independent unit; port a stratum). Secondary: conditional kill recall P(target killed | reference killed); chance-corrected kill agreement (Cohen's kappa); first-divergence tic agreement within +-1; first-field agreement; stratification by token edit distance between the two function bodies and by tier.
6. **Controls.** (a) **Within-panel permutation:** function f in P against a different function g in Q, matched on operator, reference killability stratum, coverage count and size decile; (b) **near-miss:** the matcher's second-best candidate in Q (tests whether the matcher's choice carries information); (c) **same-file, different-function** in Q; (d) **ceiling:** the same mutant, same port, rebuilt; (e) **positive control:** textually identical functions across ports; (f) within-port same-function different-site as a bound on site dependence. Empty control cells are reported.
7. **Dependence and power.** Function-level clusters (~60 before dropout), lineage strata, cluster-bootstrap 95% intervals; a power / minimum-detectable-effect calculation from pilot variances is committed with the registration. One primary (item 5); everything else descriptive or Holm-corrected.

## Predictions (thresholds set from the pilot at registration; shape fixed now)
* **S1 (primary):** primary-outcome difference, matched minus control (a), is positive with a 95% lower bound above 0 in **S-far**, and in S-near's low-similarity stratum; S-near's high-similarity stratum is expected near the ceiling and is not evidence.
* **S2:** near-miss control (b) lower than matched, with the interval excluding 0 if the pilot power allows.
* **S3 (exploratory):** agreement rises with conservation, only reported if sampling stratified cleanly.
* **S4 (decision rule):** "the matcher is role-blind at this resolution" is claimed only if the S-far lower and upper bounds of the matched-minus-control difference both lie inside a pre-set equivalence margin (set from the pilot); otherwise a null is "inconclusive".
* **S5 (interpretability):** matched pairs share the divergence class (position, health, world-hash only) more often than controls.

## Limits
Same-language C ports share inherited source, so agreement there is not independent evidence; one-token mutations are not realistic translation errors; 45 demos reach only part of each function; non-C ports may need different mutation tooling and compilers; first-differing-field shares depend on compare order (stated in E13).

## D. Reviews and reconciliation (2026-11-26)
**Both reviews agreed (adopted):** shared source makes the C-fork phase a near-tautology (stratify by source similarity, move the claim to independent lineages, doomgeneric is not independent); survivors, unreached code and hot functions make raw detection agreement and Jaccard uninterpretable (coverage per mutant, condition on reached, chance-corrected agreement, define the 0/0 case); controls must be matched on killability, coverage and size, with near-miss and ceiling/positive controls; the identical-operator-sequence filter biases toward verbatim copies (local-window alignment, dropout table, 30-site audit); selection of the top 60 is circular and confounds conservation with size (stratified frozen sample, reference-side universe); the function is the independent unit (cluster bootstrap, one primary, lineage strata, power from a pilot); first-divergence tic should enter the score; a non-confirmatory pilot comes before 2,100 builds; baseline replay of each unmutated port must pass.
**Gemini only (adopted):** self-differential scoring and the common column set (prboom-plus and inter-doom lack `prndindex`); fixed F0-then-F1c precedence (the ladder files map one port index to different reference functions in the two tiers); five tooling defects (operator order by kind not column, `#ifdef` brace tracking, macro-vs-literal constants, chocolate-only build wiring, compiler UB); the managed-doom arm.
**Claude only (adopted):** the equivalence-margin decision rule for a null; per-lineage primary tests; a prediction about the divergence class; crashes as their own category.
**Declined:** none.
