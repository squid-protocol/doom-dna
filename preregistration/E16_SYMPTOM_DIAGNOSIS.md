# E16 (v2, 2026-11-27): diagnosing a bug from its symptom with the lesion dictionary

**Status: DESIGN v2, reconciled after two independent reviews (Claude subagent; Gemini, text in `results/e15/E16_review_gemini.txt`). It becomes REGISTERED by the commit that freezes the scorer (weights, minimum demos) after the development phase below and **before** any test-set quantity (T1, T2, gore, Kocoa) is computed; that commit's hash and the demo list are part of the registration.** v1 was commit 3a679e3.
**Disclosure.** This is a **secondary analysis of the existing E15 screens** (chocolate-doom, managed-doom, prboom-plus). The E15 hot and inert masks, the exclusion of shift lesions, and the usable-function lists are taken **verbatim from E15** and not recomputed. E15 lesion outcomes have been read by the owner and me in the E15 analyses; no diagnosis quantity (ranking, top-k, baseline comparison) has been computed.

## Question
Every lesion in the chocolate-doom screen is a known small bug with a recorded symptom. If a port misbehaves, can the symptom point to the function at fault by looking it up in the lesion dictionary, better than standard coverage-based fault localisation?

## What the main test measures (stated plainly)
**T1 and T2 transplant a one-token bug into a faithful port and ask whether the reference dictionary recovers the function.** They are synthetic transfers across faithful translations, with counterpart functions chosen because they behave identically, so they are an **upper bound** for divergent ports, not an estimate of real bug localisation. The real cases (gore, Kocoa) are case studies.

## Definitions
* **Symptom vector.** For a test bug and for every dictionary lesion, over **all demos run on the test port** (77 for managed-doom and prboom-plus; the runnable shareware demos for gore and Kocoa): `killed` (first diverging tic and the E15 class set of the first diverging row: player, world, sector, keys, time; RNG bit excluded; E15 column order) or `same`. A dictionary lesion whose site never executes on a demo is coded `same` there (a real bug gives no site-level reach). Demos not run on the test port and crash/hang runs are missing. A test bug needs >= 1 kill and >= 5 evaluated demos (**minimum fixed on the development task**); a dictionary lesion with no kill on the evaluated demos scores 0.
* **Scorer** (weights frozen on the development task; a grid of non-negative weights summing to 1): (a) Jaccard of the failing-demo sets; (b) mean over mutually killed demos of the Jaccard of the class sets (0 if there are none, never renormalised); (c) mean over mutually killed demos of 1 - min(1, |log10(tic+1) differences| / the maximum observed). Function score = **maximum** over the function's lesions (primary); sensitivities: mean of the top 3 lesions, the maximum divided by the lesion count's square root, and the maximum after deduplicating identical kill vectors. **Rank** = pessimistic (ties count against the scorer); the tie-set sizes are reported. Candidates the scorer cannot rank (no co-evaluated kills) are placed **at the bottom, not removed**, so the denominator is the same for every bug.
* **Candidate list.** All E15-usable chocolate-doom functions (140). The hot and inert classes are excluded from the candidate list and from the test bugs, but **their lesions stay in the dictionary as decoys**.
* **Baselines (registered).** B1 random. **B2 Ochiai spectrum-based fault localisation on clean call coverage** (failing demos = the demos on which the test bug is `killed`, passing = all other evaluated demos; Ochiai with a safe rule when there are no passing demos; **Tarantula** as a sensitivity; reported on the usable pool and on the unfiltered pool of entered functions). B3 a **Metallaxis-style kill-only baseline** (the dictionary's binary kill vectors with the same aggregation, isolating what tic and class add). B4 a **size prior** (the number of dictionary lesions and the lines of each function). B5 **nearest neighbour on the clean call-count profile** restricted to the failing demos. B6 **call-graph proximity** (G3 distance to the functions entered on the failing demos). B7 a **demo-family-only** predictor (monsters-on versus bot demos; shareware versus Freedoom). B8 the E13 localiser recomputed on the same T1 bugs if its code allows, otherwise reported as context only (E13's 23% was a depth-three suspect-set hit rate, not a top-5 over 140 candidates).

## Protocol
1. **Development split by source file.** The 16 screened chocolate-doom files are assigned whole to a development half or a test half (alternating by function count, fixed list committed before any scoring), so sibling functions and their neighbours do not straddle the split. Functions of the test half are never used for tuning.
2. **Development task (tunes the scorer).** Managed-doom lesions whose chocolate counterpart is in the **development half** are the queries; the dictionary and the candidate list are **development-half functions only**; chance and the baselines are computed on that pool (about 70 candidates). The scorer weights, the minimum evaluated demos, and the aggregation rule are fixed here. **Viability gate:** if the frozen scorer's top-5 on the development task is below B2's + 0.10, the study stops and is reported as "the dictionary is not distinguishable from coverage-based localisation at this resolution"; no test quantity is computed.
3. **Counterpart rule** (T1, T2): the managed-doom (prboom-plus) host function has a chocolate-doom counterpart whose name agrees after prefix stripping **and** whose call-count profile is identical on all 77 demos (binary: equal counts everywhere); sensitivities: name agrees without the profile condition; **T2 excludes identical-text functions** (their results are an upper bound, reported separately).
4. **T1 (primary): managed-doom** lesions that change at least 3 demos, counterpart in the **test half**, truth = the counterpart, candidate list = all 140 usable functions, dictionary = all chocolate-doom lesions. Unit of analysis = the chocolate-doom counterpart function; every function gets equal weight (each lesion weighted 1/m_f); the share of candidate bugs dropped by the >= 3-demo filter is reported. **T2:** prboom-plus, not pooled with T1 (pooling, if reported, clusters by the chocolate-doom counterpart). **T3 (descriptive ceiling):** a chocolate-doom lesion against the dictionary with its own lesion removed (same-function siblings remain); reports the near-duplicate ceiling, not an estimate.
5. **Real cases (case studies, after T1-T3):** gore (Go) and Kocoa (Kotlin) against chocolate-doom's clean digests on the demos each port runs; the clean digests are regenerated, committed, checked on common columns (`--ignore-dead-angle`, no RNG index where the port lacks it), and checked for repeat-run determinism.

## Hypotheses and thresholds (fixed now)
* **A1 (sole confirmatory):** on T1, with Δ = top-5(dictionary) - top-5(B2 Ochiai), the **paired cluster-bootstrap 95% interval** (clusters = counterpart functions, 10,000 resamples) has a lower bound > 0 **and** the point lift Δ >= **0.15**, **and** the dictionary's top-5 >= max(**0.25**, B2's top-5 + 0.15). Power gate: at least **30** test-half counterpart functions, else "inconclusive for power". Chance (top-5 of 140) is about 3.6%; of 70, 7.1%.
* **A1b (secondary, Holm with A2):** the same on T2 (non-identical text). **A2 (secondary):** the symptom's class set alone (components (b) only plus severity bands defined on the development task) keeps the true function in the top 20% of candidates for >= the development task's rate minus 0.10 (the rate is fixed from the development task, not asserted).
* **A3 (retrospective case study, gore):** the rank of `p_CrossSubsector` **alone** (usable or hot status recorded before the run; a hot or inert truth is scored as unrankable); its 1-hop G3 callees reported separately with set-adjusted chance. **A4 (prospective case study, Kocoa):** the monster-chase family (`NewChaseDir`, `A_Chase`, `P_Move`, `P_TryWalk`, `P_CheckMissileRange`) is fixed now; hit = any in the top 10 (chance of any of five in the top 10 of 140 is about 31%); a cause is **confirmed** only by a source change that removes the divergence. Out-of-universe causes are misses. A bug that kills nearly every demo at tic < 10 matches only the (excluded) hot class and is an **expected null**.
* **Not-viable and uninterpretable outcomes (pre-declared):** failing to beat B2, B3, B4 or B7; a self-diagnosis ceiling (T3) below the A1 floor; near-hot functions filling the top-5 slots (a hub statistic is reported: the share of top-5 slots taken by the five most often returned functions); a result that holds only for one operator class.

## Controls and sensitivities
Shuffled dictionary (**functions** permuted as units): top-5 at chance. True negative: the test bug's counterpart removed from the dictionary: expected rank at chance. **Leave-operator-class-out** (diagnose `sdl` bugs with non-`sdl` lesions, and so on). Demo subsets: the original 42, shareware 58, Freedoom 19, **leave-demo-family-out**. Co-observed-demos-only scoring (the alternative to the symmetric coding). One-lesion-per-function.

## Limits
One-token lesions are not organic bugs; managed-doom and prboom-plus are faithful translations; the candidate list covers only the screened simulation files (bugs elsewhere are unrankable and counted); the 77 demos were selected greedily for coverage of both engines; the thresholds were set after the E15 analyses were read, but before any diagnosis quantity.

## D. Reviews and reconciliation (2026-11-27)
**Both reviews agreed (adopted):** leave-lesion-out leaves near-duplicate siblings (file-blocked split and cross-engine development); T1/T2 truth is partly circular and is an upper bound (stated; leave-operator-class-out and a no-profile-filter sensitivity added); scorer under-specified (components, empty cases, minimum demos, crash handling, tie reporting); max aggregation favours large functions (size prior and normalised variants); baselines incomplete (Metallaxis-style, size prior, call-graph, call-count neighbour, demo-family predictor; B2 specified; E13 recomputed or context only); thresholds must be derived (frozen floor, viability gate, power gate of 30 functions); pooled prboom-plus is not independent; gore and Kocoa are case studies, gore retrospective; out-of-universe and hot-truth cases scored as unrankable or misses; clean-digest column parity, determinism and matched demo lists; uninterpretable outcomes pre-declared (hub statistic, true-negative control, function-level shuffle).
**Claude only (adopted):** the observed-versus-unobserved mask encodes the counterpart definition, so the symmetric coding is primary and the co-observed version a sensitivity; sibling-neighbour leakage by a name hash (file-blocked split); dictionary lesions of excluded functions stay as decoys; unrankable candidates at the bottom.
**Gemini only (adopted):** secondary-analysis disclosure with E15 masks frozen verbatim; paired bootstrap on Δ and an absolute floor; equal function weighting instead of 5-lesion subsampling; Tarantula division by zero (Ochiai primary); Holm structure with A1 sole confirmatory; the `time` class (kept as defined in E15, with E15's column order).
**Declined / adjusted:** Gemini's strict dev-versus-dev tuning without managed-doom data (adopted in a combined form: cross-engine development queries against a development-half dictionary); Claude's "derive A1 as a fraction of the development ceiling" (replaced by the fixed floor plus the viability gate, to avoid open revision).
