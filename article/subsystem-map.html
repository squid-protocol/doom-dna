Call-Graph Subsystem Map LIVE DATA

All 16 subsystems are found directly from linuxdoom's call graph, with no file names (community detection, kept only where 100 runs agree; the count is a setting, about 11 to 24 depending on it). Each port's functions are placed on those subsystems through their matches to linuxdoom, then through their call-graph neighbours, so this shows where a port's functions fall among DOOM's subsystems, not an independent measure of preserved architecture. Each band is one function, shaded by how strong the evidence is: solid = a fingerprint match to the ancestor, lighter = a graph seed, faintest = an extension lead (extension keeps producing matches even on unrelated programs, so treat those as leads). Red = traces to linuxdoom; other colors = a later port the function traces to but linuxdoom does not. Grey = no ancestor found by any route, which is not proof the code is original, and for the C# and Kotlin ports means the method found nothing. Matching is the E12 ladder; seeds and extension are used only where the coherence gate passes.
